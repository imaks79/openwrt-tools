# cudy-wr3000u

Кнопка WPS на роутере Cudy WR3000U (OpenWrt, MediaTek MT7981B/Filogic)
вместо запуска WPS-подключения совмещает две функции по длительности
нажатия:

- **короткое (< 5 сек)** — в зависимости от переменной `ACTION_MODE`,
  заданной при установке:
  - `ACTION_MODE=wifi` (по умолчанию) — переключает Wi-Fi целиком (оба
    диапазона разом) и синхронно зажигает/гасит два диапазонных
    светодиода на панели (2.4 ГГц и 5 ГГц), отражая новое состояние
    радио;
  - `ACTION_MODE=wan` — блокирует/разблокирует форвардинг LAN→WAN
    файрволом, оставляя Wi-Fi/LAN/USB-шару доступными (приватное
    использование SMB-шары без выхода в интернет), индикация через
    `red:fault`;
  - `ACTION_MODE=netbird` — включает/выключает подключение
    [netbird](https://netbird.io/) (`netbird up`/`netbird down`),
    индикация через оба диапазонных LED разом. Требует уже установленного
    и настроенного netbird;
- **долгое (≥ 5 сек)** — безопасно монтирует/размонтирует USB-накопитель,
  чтобы не заходить по SSH ради размонтирования перед извлечением флешки
  (не зависит от `ACTION_MODE` — работает всегда). WR3000U аппаратно
  имеет USB-порт (xhci/usb_phy включены в device tree,
  `mt7981b-cudy-wbr3000uax-v1.dtsi`). Требует, чтобы сетевая шара уже
  была настроена универсальным
  [`openwrt-tool/usb-smb-share.sh`](../openwrt-tool/README.md).

## Быстрый старт

На роутере включён SSH. Подключайтесь **по кабелю/LAN**, не по Wi-Fi —
см. предупреждение ниже.

```sh
wget -O - https://raw.githubusercontent.com/imaks79/openwrt-tools/main/cudy-wr3000u/install-wps-button.sh | sh
```

Чтобы короткое нажатие блокировало WAN вместо Wi-Fi:

```sh
ACTION_MODE=wan \
  wget -O - https://raw.githubusercontent.com/imaks79/openwrt-tools/main/cudy-wr3000u/install-wps-button.sh | sh
```

Чтобы короткое нажатие включало/выключало netbird вместо Wi-Fi:

```sh
ACTION_MODE=netbird \
  wget -O - https://raw.githubusercontent.com/imaks79/openwrt-tools/main/cudy-wr3000u/install-wps-button.sh | sh
```

Скрипт скачивает `wps-button-wifi-toggle.sh` и кладёт его в
`/etc/rc.button/wps` — так называется хук, который procd вызывает на
каждое физическое нажатие кнопки WPS (модуль ядра `button-hotplug`
переводит `linux,code=KEY_WPS_BUTTON` из device tree в переменную
`BUTTON="wps"`). Если на роутере уже был свой `/etc/rc.button/wps`
(например, реальная обработка WPS), он сохраняется рядом как
`/etc/rc.button/wps.orig`. Путь добавляется в `/etc/sysupgrade.conf`, чтобы
пережить `sysupgrade` (без `-n` сохраняются только файлы из этого списка).

## Имена светодиодов

Подтверждены командой `ls /sys/class/leds/` на реальном Cudy WR3000U
(OpenWrt):

```
blue:lan         blue:wan         blue:wlan-2ghz   mt76-phy0        red:fault
blue:power       blue:wan-online  blue:wlan-5ghz   mt76-phy1        red:wps
```

Скрипт по умолчанию использует `blue:wlan-2ghz` и `blue:wlan-5ghz` —
диапазонные индикаторы 2.4 ГГц/5 ГГц. Несмотря на то, что на панели они
могут восприниматься как красные, в системе они зарегистрированы именно
под этими именами (совпадает с upstream device tree,
`mt7981b-cudy-wbr3000uax-v1.dtsi`). Отдельно существует `red:wps` (сама
кнопка) — его скрипт не трогает. `red:fault` в режиме `ACTION_MODE=wifi`
тоже не трогается (штатно управляется системой автоматически как
индикатор "Internet offline"), но в режиме `ACTION_MODE=wan` скрипт
временно берёт его под ручное управление, чтобы показывать блокировку
WAN. В режиме `ACTION_MODE=netbird` сам Wi-Fi этой кнопкой не
переключается, поэтому диапазонные LED (`blue:wlan-2ghz`/`blue:wlan-5ghz`)
свободны и переиспользуются для индикации состояния netbird.

Если на вашей прошивке/ревизии платы вывод `ls /sys/class/leds/`
отличается, переопределите имена перед установкой:

```sh
LED_2G_DIR=/sys/class/leds/<имя> LED_5G_DIR=/sys/class/leds/<имя> \
  wget -O - https://raw.githubusercontent.com/imaks79/openwrt-tools/main/cudy-wr3000u/install-wps-button.sh | sh
```

Установщик также печатает содержимое `/sys/class/leds/` в конце для
сверки.

### Про "красные" диапазонные LED

Изначально предполагалось, что у диапазонных индикаторов есть отдельный
красный цвет (два физических LED, по одному на диапазон). Проверка на
реальном устройстве это не подтвердила:

- в системе для диапазонов зарегистрированы только `blue:wlan-2ghz` и
  `blue:wlan-5ghz` — других LED-имён, привязанных к диапазону, нет;
- `red:fault` и `red:wps` существуют, но не привязаны к диапазону
  (`red:fault` — общий, не про Wi-Fi; `red:wps` — LED самой кнопки), и оба
  при ручной проверке (`echo` в `brightness` через `trigger=none`)
  физически не отреагировали — судя по всему, на этой ревизии платы
  (WR3000U, бюджетная 256 МБ ревизия) `red:fault` в device tree объявлен,
  но не распаян;
- по описанию с панели пользователь тоже не смог однозначно подтвердить
  наличие отдельного красного цвета у диапазонных индикаторов.

**Важно для режима `ACTION_MODE=wan`:** индикация блокировки WAN
использует именно `red:fault` (см. ниже) — а он, по итогам проверки выше,
на этой ревизии платы физически не реагирует на ручное управление.
Практически это означает, что сама блокировка форвардинга будет работать,
но видимого светового сигнала может не быть — проверяйте состояние через
`logread` (тег `rc.button.wps`), а не по LED. Если на вашей ревизии платы
`red:fault` всё же распаян и реагирует — индикация заработает как задумано.

Вывод: на этой модели диапазонные LED, по всей видимости, **только
синие** — скрипт управляет именно ими (`blue:wlan-2ghz`/`blue:wlan-5ghz`,
включаются/гаснут по состоянию своего диапазона), и это единственный
подтверждённый работающий индикатор. Если на вашей ревизии платы всё же
есть отдельный красный канал под другим именем — пришлите вывод
`ls /sys/class/leds/` и результат ручной проверки, добавим поддержку.

## Логика

Длительность нажатия читается из переменной `SEEN`, которую модуль ядра
`button-hotplug` добавляет к каждому событию кнопки (число полных секунд
с предыдущего события для этой кнопки) — реального удержания в реальном
времени ждать не нужно, всё решается по факту отпускания
(`ACTION=released`): `SEEN<5` — короткое нажатие (Wi-Fi), `SEEN>=5` —
долгое (USB).

### Короткое нажатие — Wi-Fi

У кнопки WPS, в отличие от флажка "mode" на Cudy TR3000, нет двух
устойчивых положений — только "нажата"/"отпущена". Поэтому желаемое
состояние сети не читается из положения кнопки, а вычисляется инверсией
текущего:

- если хотя бы одна секция `wifi-device` в `/etc/config/wireless` сейчас
  включена (`disabled=0`) — выключаются **все**;
- если все уже выключены — включаются **все**.

Соответствие диапазон → LED берётся из `option band '2g'/'5g'` секций
`wireless.radioN` (стандартное поле конфигурации в OpenWrt 21.02+), а не
из порядка `radio0`/`radio1` — так соответствие остаётся верным, даже
если в конкретной сборке порядок радиомодулей другой. После переключения
светодиод своего диапазона зажигается, если этот диапазон включён, и
гаснет, если выключен.

### Короткое нажатие — блокировка WAN (`ACTION_MODE=wan`)

Альтернатива Wi-Fi-переключателю: короткое нажатие блокирует/снимает
блокировку форвардинга LAN→WAN файрволом (все секции `forwarding` в
`/etc/config/firewall` с `dest='wan'`, независимо от исходной зоны — lan,
guest и т.п.). Wi-Fi, LAN и USB-шара продолжают работать — можно приватно
попользоваться SMB-шарой через недоверенную сеть без выхода в интернет.
Желаемое состояние, как и в режиме `wifi`, вычисляется инверсией текущего
(по наличию хотя бы одного включённого forwarding-правила в зону `wan`).

Индикация — светодиод `red:fault` (штатно означает "Internet offline",
семантически подходит). **Важно:** на бюджетной 256MB-ревизии этой платы
он не распаян физически (см. предупреждение в разделе про LED выше) —
если LED не загорается, проверяйте результат через `logread`.

### Короткое нажатие — netbird (`ACTION_MODE=netbird`)

Включает/выключает подключение [netbird](https://netbird.io/) командами
`netbird up`/`netbird down` (демон/сервис не трогаем — предполагается,
что уже запущен и залогинен через `netbird login --setup-key <KEY>`).
Желаемое состояние вычисляется инверсией текущего — по первой строке
`netbird status` (`Daemon status: Connected` при установленном
соединении). Если бинарь `netbird` не найден в `PATH` — логируется
предупреждение через `logger` и ничего не делается.

Индикация — оба диапазонных LED (`blue:wlan-2ghz`/`blue:wlan-5ghz`) разом:
горят, пока netbird отключён, гаснут при подключении. В этом режиме сам
Wi-Fi кнопкой не переключается, поэтому реальное состояние радио они
больше не отражают.

### Долгое нажатие (5+ сек) — USB-накопитель

Требует, чтобы шара уже была настроена
[`openwrt-tool/usb-smb-share.sh`](../openwrt-tool/README.md) — точка
монтирования читается из той же UCI-секции, которую он настраивает
(`fstab.usbmount.target`, по умолчанию `/mnt/usb1`, если секции ещё нет).

- **накопитель сейчас смонтирован** — безопасно размонтируется (обычный
  `umount`, как перед физическим извлечением);
- **накопитель сейчас не смонтирован** — выполняется
  `OPENWRT_TOOL_MODE=swap-disk sh /root/openwrt-tool/usb-smb-share.sh`,
  чтобы подхватить другой физически подключённый накопитель — `swap-disk`
  сам определяет его файловую систему и обновляет UUID в `fstab.usbmount`
  (нюансы поведения — ниже).

Если `openwrt-tool/usb-smb-share.sh` ещё не устанавливался на этом
роутере — долгое нажатие просто пишет предупреждение через `logger` и
ничего не делает (без ошибок и без попытки смонтировать вслепую).
Результат каждого нажатия смотрите через `logread` (тег `rc.button.wps`);
вывод самого `swap-disk` пишется в
`/root/openwrt-tool/wps-button-swap-disk.log`.

Особенности режима `swap-disk` (общие для всех кнопок, использующих этот
режим — подробнее см. [openwrt-tool/README.md](../openwrt-tool/README.md)):

- **Не требует интернета**, если драйвер под файловую систему накопителя
  уже установлен (обычно так и есть) — сеть понадобится только для
  файловой системы, которая на этом роутере ещё ни разу не использовалась.
- **Игнорирует прежний физический диск по UUID** при поиске — из-за этого
  второе долгое нажатие подряд, если накопитель физически не меняли (тот
  же диск всё ещё воткнут), **не** смонтирует его обратно мгновенно, как
  могло быть раньше: `swap-disk` теперь честно ждёт до 60 секунд появления
  действительно ДРУГОГО накопителя и, не найдя его, завершается ошибкой —
  сам диск при этом уже безопасно отмонтирован первым нажатием, его можно
  спокойно извлекать. Если же извлекать его не хотели и нужен обратно тот
  же самый накопитель — `swap-disk` для этого не годится (он ищет именно
  другой диск); проще всего физически вынуть и снова вставить накопитель
  (новое USB-подключение роутер подхватит по уже настроенному в
  `fstab.usbmount` UUID автоматически, без кнопки и без `swap-disk`), либо
  смонтировать вручную по SSH (`block mount`).
- **Несколько разделов на одном накопителе** (например, Ventoy: основной
  раздел + маленький EFI) — без интерактивного терминала (а у кнопки его
  нет) автоматически выбирается раздел **наибольшего размера** вместо
  отказа.
- Если одновременно подключено **несколько разных** физических
  накопителей — по той же причине (нет терминала для выбора) автоматически
  выбирается тот, у которого больше раздел. Чтобы подключить конкретный
  из нескольких — подключайте по одному за раз, либо выбирайте явно через
  SSH: `OPENWRT_TOOL_MODE=swap-disk sh /root/openwrt-tool/usb-smb-share.sh`.

## ВНИМАНИЕ: SSH по Wi-Fi

Если вы зашли по SSH через сам Wi-Fi (а не по кабелю/LAN) — нажатие
кнопки может выключить Wi-Fi и оборвать вашу же SSH-сессию вместе с
сетью. Тестируйте и устанавливайте по кабелю.

## Проверка без физической кнопки

Короткое нажатие (Wi-Fi) — запустите дважды подряд: первый раз выключит
Wi-Fi (диапазонные LED должны погаснуть), второй раз включит обратно (LED
должны загореться):

```sh
SEEN=0 ACTION=released BUTTON=wps /etc/rc.button/wps
```

Короткое нажатие в режиме `wan`, без переустановки скрипта — запустите
дважды подряд, аналогично:

```sh
ACTION_MODE=wan SEEN=0 ACTION=released BUTTON=wps /etc/rc.button/wps
```

Короткое нажатие в режиме `netbird`, без переустановки скрипта (требует
уже настроенного netbird):

```sh
ACTION_MODE=netbird SEEN=0 ACTION=released BUTTON=wps /etc/rc.button/wps
```

Долгое нажатие (USB, требует уже настроенной шары) — если накопитель
смонтирован, первый запуск его безопасно размонтирует:

```sh
SEEN=5 ACTION=released BUTTON=wps /etc/rc.button/wps
```

Повторный запуск теперь смонтирует только **другой** физический
накопитель (см. «Особенности режима swap-disk» выше) — чтобы проверить
именно эту ветку, физически замените накопитель перед вторым запуском,
иначе он честно прождёт 60 секунд и завершится ошибкой (сам первый диск
при этом уже отмонтирован, это нормально).

## Если форкаете этот проект

Этот каталог — часть монорепозитория
[openwrt-tools](https://github.com/imaks79/openwrt-tools). Если
переносите **именно этот каталог** в отдельный репозиторий — поменяйте
`<USER>/<REPO>` в переменной `SCRIPT_URL` в `install-wps-button.sh`:

```sh
grep -n '^SCRIPT_URL=' install-wps-button.sh
```
