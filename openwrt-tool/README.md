# openwrt-tool

Два независимых универсальных скрипта для роутеров с прошивкой OpenWrt —
каждый запускается одной строкой через SSH и не привязан к конкретной
модели роутера:

- **[`install.sh`](#installsh--первоначальная-настройка--adguard-home)** —
  первоначальная настройка чистого роутера (обновление системы, AdGuard
  Home, podkop, тема LuCI, сетевые UCI-настройки). Требует apk-сборку
  OpenWrt (23.05+/24.10+).
- **[`usb-smb-share.sh`](#usb-smb-sharesh--usb-накопитель-в-сетевую-smb-шару)** —
  USB-накопитель → сетевая SMB-шара (ksmbd или Samba4, выбор диалогом).
  Работает на любом роутере с OpenWrt (opkg или apk), у которого есть
  USB-порт.

---

## `install.sh` — первоначальная настройка + AdGuard Home

Разворачивает на роутере типовую конфигурацию: обновление системы,
AdGuard Home, podkop, тему LuCI и сетевые UCI-настройки — всё в один
проход, без ручного вмешательства между шагами.

### Быстрый старт

Подключитесь к роутеру по SSH и вставьте одну строку (hostname по
умолчанию `OpenWrt`):

```sh
wget -O - https://raw.githubusercontent.com/imaks79/openwrt-tools/main/openwrt-tool/install.sh | sh
```

Роутер сам обновится, установит пакеты, применит конфиг AdGuard Home и
сетевые настройки, дважды перезагрузится и на этом закончит — повторно
заходить по SSH не нужно.

С уникальным именем роутера (полезно при массовой настройке нескольких
устройств одновременно). Качаем сразу в `/root/openwrt-tool/install.sh` —
именно туда скрипт сохраняет себя сам при первом запуске (см.
«Как это работает» ниже), поэтому при таком пути повторного скачивания
не будет и файл на диске сразу совпадёт с тем, что дальше использует
hook после перезагрузки:

```sh
mkdir -p /root/openwrt-tool
wget -O /root/openwrt-tool/install.sh https://raw.githubusercontent.com/imaks79/openwrt-tools/main/openwrt-tool/install.sh
OPENWRT_TOOL_HOSTNAME=router-05 sh /root/openwrt-tool/install.sh
```

Со своим адресом LAN вместо `192.168.3.1` (подставится сразу везде: в
`network.lan.ipaddr`, DNS-опцию DHCP и конфиг AdGuard Home — вручную
ничего досогласовывать не нужно; маска подсети всегда `/24`):

```sh
mkdir -p /root/openwrt-tool
wget -O /root/openwrt-tool/install.sh https://raw.githubusercontent.com/imaks79/openwrt-tools/main/openwrt-tool/install.sh
OPENWRT_TOOL_LAN_IP=192.168.50.1 sh /root/openwrt-tool/install.sh
```

Тот же вариант одной строкой (без сохранения файла заранее):

```sh
wget -O - https://raw.githubusercontent.com/imaks79/openwrt-tools/main/openwrt-tool/install.sh | OPENWRT_TOOL_LAN_IP=192.168.50.1 sh
```

Адрес должен быть в форме `A.B.C.D`, последний октет не может быть `0`
или `255`, и не должен попадать в диапазон DHCP-пула (по умолчанию
`.100`–`.249`) — иначе скрипт откажется стартовать и объяснит причину.

### Как это работает

Исходные настройки были собраны из двух источников: конфига AdGuard Home
(`/etc/adguardhome/adguardhome.yaml`) и трёх блоков команд для роутера
(обновление системы, установка пакетов, сетевые UCI-настройки).
`install.sh` объединяет всё это в один файл. Особенность в том, что первый
блок команд заканчивается перезагрузкой роутера — простой `wget | sh` этого
не переживёт. Поэтому скрипт:

1. при первом запуске сохраняет себя в `/root/openwrt-tool/install.sh`;
2. хранит прогресс в `/etc/openwrt-tool.stage` (`1` → обновление,
   `2` → пакеты и конфиги, `3` → готово);
3. перед каждой перезагрузкой регистрирует одноразовый хук в `/etc/rc.local`,
   который вызывает сохранённую копию скрипта после старта системы;
4. после последнего этапа хук из `rc.local` удаляется.

Итого роутер сам уходит на 2 перезагрузки и полностью настраивается без
повторных заходов по SSH.

### Пароль AdGuard Home

Логин/пароль по умолчанию — `root` / `root`. Это временный пароль для
первого входа, **смените его сразу после установки** через веб-интерфейс
AdGuard Home, либо заранее сгенерируйте свой хэш и подставьте в
`password:` внутри `install.sh`:

```sh
htpasswd -bnBC 10 "" 'ваш_пароль' | cut -d: -f2
```

### Логи и повторный запуск

Ход выполнения пишется в `/root/openwrt-tool/install.log`. Если нужно
прогнать настройку заново с начала:

```sh
rm -f /etc/openwrt-tool.stage
sh /root/openwrt-tool/install.sh
```

### Отличие от исходных шаблонов

- Настройки собраны в один файл — не нужно вручную копировать YAML на роутер.
- Добавлено ожидание сети (до ~60 сек) перед каждым `apk update`, так как
  после ребута интернет поднимается не мгновенно.
- Установка `podkop` и темы LuCI обёрнута так, чтобы их сбой не прерывал
  остальную настройку (AdGuard Home и сетевые параметры всё равно применятся).
- Добавлен `uci commit attendedsysupgrade` — в исходном шаблоне опция
  `login_check_for_upgrades` выставлялась через `uci set`, но не коммитилась
  и поэтому не сохранялась.
- Hostname можно переопределить через переменную окружения
  `OPENWRT_TOOL_HOSTNAME`.
- Адрес LAN можно переопределить через `OPENWRT_TOOL_LAN_IP` — значение
  подставляется во все зависимые параметры одновременно, что исключает
  рассинхронизацию между ними.

## `usb-smb-share.sh` — USB-накопитель в сетевую SMB-шару

Превращает USB-порт роутера в сетевой общий каталог (SMB/CIFS) —
доступный с Windows, macOS, Linux, Android и iOS. SMB-сервер выбирается
диалогом прямо в SSH-сессии:

- **ksmbd** — облегчённый (в ядре Linux), меньше нагружает флеш/память,
  рекомендуется на роутерах с малым флешем (вариант по умолчанию, просто
  Enter);
- **samba4** — полноценный Samba, больше функций и совместимости, тяжелее.

Переустановиться на другой вариант можно в любой момент отдельной командой
(`OPENWRT_TOOL_MODE=smb-backend`, см. ниже) — без переразметки диска.

### Совместимость: какие роутеры подходят

Скрипт не привязан ни к одной конкретной модели — используются только
стандартные пакеты OpenWrt (`opkg`/`apk`) и стандартная UCI-схема
(`fstab`/`network`/`firewall`), без специфичных для одного устройства
путей. Реальные условия:

- физический **USB-порт** на роутере (у многих бюджетных моделей его
  просто нет — скрипт ждёт накопитель 60 сек и останавливается с понятным
  сообщением, ничего не ломая);
- пакетный менеджер `opkg` или `apk` — это покрывает весь мейнстрим
  OpenWrt 19.07…25.x;
- достаточно свободного **флеша** под пакеты (`ksmbd` лёгкий, `samba4` не
  всегда влезет на роутеры с 4–8 МБ флеша);
- `kmod-usb3`/`kmod-usb-storage-uas` ставятся, только если они вообще есть
  в индексе пакетов конкретной прошивки (на чисто USB 2.0 платформах их
  может не быть) — отсутствие этих ускорителей не прерывает установку.

Опробовано на Cudy TR3000 (256 МБ флеша, mediatek/filogic).

### Быстрый старт

На роутере включён SSH, к USB-порту подключён накопитель (можно подключить
и позже — скрипт подождёт до 60 секунд), отформатированный **заранее** в
`ext4` (рекомендуется), `exfat`, `ntfs3`, `vfat` (FAT32) или `f2fs` — сам
скрипт диск не форматирует и не размечает (осознанное ограничение, чтобы
случайно не стереть чужие данные).

Подключитесь к роутеру по SSH и вставьте одну строку:

```sh
wget -O - https://raw.githubusercontent.com/imaks79/openwrt-tools/main/openwrt-tool/usb-smb-share.sh | sh
```

Первым делом скрипт спросит, какой SMB-сервер ставить:

```
Выберите SMB-сервер для сетевой шары:
  1) ksmbd  — облегчённый (в ядре Linux), меньше нагружает флеш/память (по умолчанию)
  2) samba4 — полноценный Samba, больше функций и совместимости, тяжелее
Ваш выбор [1]:
```

Затем роутер сам обновит списки пакетов, поставит нужные модули (USB,
файловая система, выбранный SMB-сервер), найдёт накопитель, настроит
автомонтирование по UUID и сетевую шару. В процессе один раз **дважды
попросит ввести пароль** для нового SMB-пользователя (по умолчанию
`smbuser`) — обычный интерактивный ввод внутри SSH-сессии, пароль нигде на
диске не сохраняется. Перезагрузка роутеру не требуется.

Чтобы не отвечать на вопрос (например, при автоматическом развёртывании),
задайте `OPENWRT_TOOL_SMB_BACKEND=ksmbd` или `OPENWRT_TOOL_SMB_BACKEND=samba4`
заранее.

### Как это работает

Особенность в том, что при запуске через `wget -O - ... | sh` стандартный
ввод самого скрипта уже занят телом скрипта, поэтому диалог выбора
SMB-сервера, выбор раздела (если к роутеру подключено сразу несколько
USB-накопителей) и создание SMB-пользователя (`ksmbd.adduser`/`smbpasswd`)
— все эти места явно читают ответ/пароль из `/dev/tty`, реального
терминала SSH-сессии, а не из перекрытого stdin. Без этого, например,
`ksmbd.adduser` мгновенно получил бы EOF вместо пароля и завершился, так и
не дав его ввести.

Настройка не требует перезагрузки роутера, поэтому скрипту не нужно
переживать ребут и продолжать себя после него — вся работа укладывается в
один проход. Скрипт всё же сохраняет свою копию в
`/root/openwrt-tool/usb-smb-share.sh`, чтобы дальнейшие команды (статус,
смена диска, смена SMB-сервера, cron-алерт) можно было запускать повторно
без повторного скачивания.

### Переменные окружения

Все опциональны, задаются перед командой:

```
OPENWRT_TOOL_MOUNT_POINT      точка монтирования USB (по умолчанию /mnt/usb1)
OPENWRT_TOOL_FS_TYPE          ext4 | exfat | ntfs3 | vfat | f2fs (по умолчанию ext4)
OPENWRT_TOOL_SHARE_NAME       имя сетевой шары (по умолчанию share)
OPENWRT_TOOL_WORKGROUP        рабочая группа SMB (по умолчанию WORKGROUP)
OPENWRT_TOOL_SMB_USER         логин для доступа к шаре (по умолчанию smbuser)
OPENWRT_TOOL_SMB_BACKEND      ksmbd | samba4 — если не задано, спросит диалогом
OPENWRT_TOOL_GUEST            1 — разрешить анонимный доступ (не рекомендуется)
OPENWRT_TOOL_WITH_CRON_ALERT  1 — сразу поставить ежедневную проверку заполнения диска
OPENWRT_TOOL_USER_ACTION      add|passwd|delete|list — неинтерактивное управление
                               пользователями (режим users, см. ниже); без неё —
                               интерактивное меню
OPENWRT_TOOL_MODE             setup (по умолчанию) | status | swap-disk |
                               smb-backend | users | cron-alert
```

Не путайте с переменными `OPENWRT_TOOL_HOSTNAME`/`OPENWRT_TOOL_LAN_IP` у
соседнего `install.sh` — это два независимых скрипта с разными наборами
переменных, оба с префиксом `OPENWRT_TOOL_` просто для единообразия.

#### Примеры

Накопитель в exFAT и своё имя шары:

```sh
OPENWRT_TOOL_FS_TYPE=exfat OPENWRT_TOOL_SHARE_NAME=movies \
  wget -O - https://raw.githubusercontent.com/imaks79/openwrt-tools/main/openwrt-tool/usb-smb-share.sh | sh
```

Настройка сразу с ежедневным алертом о заполнении диска:

```sh
OPENWRT_TOOL_WITH_CRON_ALERT=1 \
  wget -O - https://raw.githubusercontent.com/imaks79/openwrt-tools/main/openwrt-tool/usb-smb-share.sh | sh
```

Гостевой (анонимный) доступ без пароля:

```sh
OPENWRT_TOOL_GUEST=1 \
  wget -O - https://raw.githubusercontent.com/imaks79/openwrt-tools/main/openwrt-tool/usb-smb-share.sh | sh
```

Сразу поставить полноценный Samba4, без вопроса:

```sh
OPENWRT_TOOL_SMB_BACKEND=samba4 \
  wget -O - https://raw.githubusercontent.com/imaks79/openwrt-tools/main/openwrt-tool/usb-smb-share.sh | sh
```

### Режимы после первоначальной настройки

Скрипт сохраняет себя в `/root/openwrt-tool/usb-smb-share.sh` — эти
команды выполняются на роутере и не требуют переустановки пакетов:

**Статус** (место на диске, скорость линка USB, статус SMB-службы, логи):

```sh
OPENWRT_TOOL_MODE=status sh /root/openwrt-tool/usb-smb-share.sh
```

**Смена физического накопителя** (другая флешка/диск, другой UUID,
возможно другая файловая система) — отмонтирует старый накопитель,
дождётся (до 60 сек) нового, определит его файловую систему автоматически
(ext4/exfat/vfat/ntfs/f2fs — доустановит нужный модуль при необходимости,
включая откат ntfs3→ntfs-3g), обновит точку монтирования. Шара, логин и
пароль остаются прежними — клиентам ничего менять не нужно:

```sh
OPENWRT_TOOL_MODE=swap-disk sh /root/openwrt-tool/usb-smb-share.sh
```

Если это **та же самая флешка** (просто вынули/вставили обратно, или после
перезагрузки роутера) — запускать ничего не нужно. Монтирование привязано
к UUID конкретного накопителя (`/etc/config/fstab`), и роутер сам
примонтирует его и поднимет шару по прежнему пути.

Если это **другой, ещё не зарегистрированный накопитель** — сам по себе он
**не** примонтируется автоматически при подключении, и это ожидаемо: у
OpenWrt автомонтаж (`fstab.@global[0].anon_mount`) по умолчанию выключен —
подключается только UUID, уже прописанный в `fstab.usbmount`. Так и
задумано (иначе любая случайно воткнутая флешка монтировалась бы сама).
Именно поэтому существует `swap-disk`/долгое нажатие кнопки (см. кнопки в
`cudy-tr3000`/`cudy-wr3000u`) — они прописывают
UUID нового накопителя в `fstab.usbmount`, после чего именно ЭТОТ
накопитель начинает подхватываться автоматически при последующих
подключениях/перезагрузках.

**Переустановка/переключение SMB-сервера** (ksmbd ↔ samba4) на уже
настроенной шаре — диск и точка монтирования не трогаются:

```sh
OPENWRT_TOOL_MODE=smb-backend sh /root/openwrt-tool/usb-smb-share.sh
```

Спросит тем же диалогом, какой backend поставить. Если выбран **другой**
backend, чем сейчас активен — старый останавливается, отключается и
**удаляется** (`opkg remove`/`apk del`), чтобы на флеше не висели сразу два
SMB-сервера, новый ставится и настраивается с нуля. Пароль SMB-пользователя
будет запрошен заново — базы паролей ksmbd (`ksmbd.adduser`) и samba4
(`smbpasswd`) отдельные и не переносятся друг в друга. Если выбран **тот
же** backend — это просто переустановка поверх текущей конфигурации
(например, чтобы сменить пароль). Имя шары, workgroup, гостевой доступ и
точка монтирования берутся из тех же переменных окружения/значений по
умолчанию, что и при обычной установке. Как и `OPENWRT_TOOL_MODE=setup`,
эта команда требует, чтобы шара уже была настроена (`setup` хотя бы раз
выполнялся).

**Управление пользователями SMB** — добавить нового, сменить пароль
существующему или убрать доступ, не трогая ни диск, ни сам SMB-сервер.
Не требует сети (пакеты не ставятся) и работает мгновенно:

```sh
OPENWRT_TOOL_MODE=users sh /root/openwrt-tool/usb-smb-share.sh
```

Без дополнительных переменных открывается интерактивное меню прямо в
SSH-сессии:

```
Управление пользователями SMB (backend: ksmbd)
Текущие пользователи шары: smbuser
  1) Добавить пользователя / задать пароль
  2) Сменить пароль существующему
  3) Удалить пользователя
  4) Показать список и выйти
Выбор [4]:
```

Пункт 1 работает и для уже существующего логина — тогда это просто смена
пароля. Для одной команды без меню (автоматизация, скрипты) — тот же режим
плюс `OPENWRT_TOOL_USER_ACTION`:

```sh
# Добавить второго пользователя (или сменить пароль, если уже есть)
OPENWRT_TOOL_MODE=users OPENWRT_TOOL_USER_ACTION=add OPENWRT_TOOL_SMB_USER=family \
  sh /root/openwrt-tool/usb-smb-share.sh

# Сменить пароль существующему
OPENWRT_TOOL_MODE=users OPENWRT_TOOL_USER_ACTION=passwd OPENWRT_TOOL_SMB_USER=family \
  sh /root/openwrt-tool/usb-smb-share.sh

# Убрать доступ (и из базы backend'а, и из списка users шары)
OPENWRT_TOOL_MODE=users OPENWRT_TOOL_USER_ACTION=delete OPENWRT_TOOL_SMB_USER=family \
  sh /root/openwrt-tool/usb-smb-share.sh

# Только посмотреть список, без изменений
OPENWRT_TOOL_MODE=users OPENWRT_TOOL_USER_ACTION=list \
  sh /root/openwrt-tool/usb-smb-share.sh
```

Для `passwd`/`delete` `OPENWRT_TOOL_SMB_USER` нужно указать **явно** — у
переменной есть дефолт `smbuser` (основной пользователь, созданный при
`setup`), но неинтерактивные `passwd`/`delete` намеренно отказываются
запускаться без явного имени: иначе забытая переменная случайно сменила
бы пароль или удалила пользователя по умолчанию вместо ожидаемой ошибки.
Для `add` дефолт безопасен и подходит — так `OPENWRT_TOOL_MODE=users
OPENWRT_TOOL_USER_ACTION=add sh ...` без переменных просто пересоздаёт
пароль `smbuser`, как при `setup`.

Список пользователей хранится в той же UCI-опции, что и на шаге `setup`
(`<backend>.usbshare.users`) — добавление/удаление правит её автоматически,
руками в UCI лезть не нужно. Для samba4 при добавлении нового логина
скрипт сам заводит под него служебную unix-запись в `/etc/passwd` (см.
раздел «Известные особенности» ниже) — то же самое, что уже делает `setup`
для первого пользователя.

**Ежедневный алерт о заполнении диска** отдельно от первоначальной
настройки (пишет в syslog предупреждение, если диск заполнен на 90% и
более, тег лога `usb-storage-alert`):

```sh
OPENWRT_TOOL_MODE=cron-alert sh /root/openwrt-tool/usb-smb-share.sh
```

Посмотреть сработавшие алерты:

```sh
logread | grep usb-storage-alert
```

Скрипт идемпотентен: `OPENWRT_TOOL_MODE=setup` можно запускать повторно
(например, чтобы поменять параметры) — старые UCI-секции с тем же именем
удаляются перед созданием новых.

### Что скрипт делает на роутере (режим setup)

1. Спрашивает диалогом, какой SMB-сервер поставить — `ksmbd` (по умолчанию)
   или `samba4` (если не задан `OPENWRT_TOOL_SMB_BACKEND`).
2. Обновление списков пакетов (`apk update` на OpenWrt 25.x, `opkg update`
   на более старых прошивках — скрипт сам определяет, что есть в системе)
   и установка пакетов: `kmod-usb-storage`, `block-mount`, `e2fsprogs`,
   `fdisk` (плюс `kmod-usb3`/`kmod-usb-storage-uas`, если они есть в
   индексе — см. раздел про совместимость выше), модуль нужной файловой
   системы, и `ksmbd-server` + `luci-app-ksmbd` (либо `samba4-server` +
   `luci-app-samba4`, если выбран `samba4`; если выбран `ksmbd`, но он
   недоступен в индексе пакетов прошивки — скрипт останавливается с
   понятным сообщением, вместо тихого отката).
3. Ищет подключённый USB-накопитель **строго среди `/dev/sdX`** (так в
   OpenWrt всегда называются диски, подключённые через USB-storage) —
   внутренние разделы прошивки роутера никогда не трогаются. Если
   накопитель ещё не подключён, скрипт **ждёт до 60 секунд**, опрашивая
   каждые 3 секунды. Если найдено несколько разделов — спросит, какой
   использовать (ответ читается из `/dev/tty`).
4. Настраивает автомонтирование по UUID через UCI (`/etc/config/fstab`) —
   монтирование переживёт перезагрузку и не зависит от того, в каком
   порядке система пронумеровала диски.
5. Создаёт SMB-шару, ограниченную только что созданным пользователем
   (`OPENWRT_TOOL_GUEST=1` снимает это ограничение).
6. Создаёт SMB-пользователя и запрашивает пароль интерактивно.
7. Включает и перезапускает SMB-службу.
8. (опционально, `OPENWRT_TOOL_WITH_CRON_ALERT=1`) Ставит cron-задачу,
   которая раз в день в 08:00 пишет в syslog предупреждение, если диск
   заполнен на 90% и более.
9. Печатает текущий статус (как в режиме `status`).

### Как пользоваться готовой шарой

- **Windows**: в проводнике `\\<ip роутера>\share`, ввести логин/пароль.
- **macOS**: Finder → `Cmd+K` → `smb://<ip роутера>/share`.
- **Linux**: `smb://<ip роутера>/share` в файловом менеджере, либо
  `sudo mount -t cifs //<ip роутера>/share /mnt/point -o username=smbuser`.
- **Android/iOS**: любое приложение с поддержкой SMB (Solid Explorer,
  FE File Explorer и т.п.), сервер `<ip роутера>`, шара `share`.

Перед физическим отключением накопителя — размонтировать на роутере:

```sh
umount /mnt/usb1
```

### Мониторинг

В любой момент, прямо на роутере:

```sh
OPENWRT_TOOL_MODE=status sh /root/openwrt-tool/usb-smb-share.sh
```

Покажет: настроенный SMB-backend, место на диске, скорость линка USB
(`5000` = USB 3.0, `480` = USB 2.0 — если видите 480, проверьте
кабель/порт), статус SMB-службы, последние сообщения ядра про USB и
последние записи журнала по SMB.

Через LuCI (веб-интерфейс роутера): **System → Mount Points** — список
смонтированных дисков; **Services → Network Shares** (после установки
`luci-app-ksmbd`/`luci-app-samba4`) — активные шары.

### Известные особенности

- **samba4 заводит системного пользователя в `/etc/passwd`.** Шаблон
  пакета `samba4` в OpenWrt использует `passdb backend = smbpasswd` —
  этому классическому бэкенду для `smbpasswd -a` обязательно нужна
  одноимённая запись в `/etc/passwd` (иначе падает с ошибкой `Failed to
  add entry for user <имя>.`). Скрипт сам дописывает такую запись (shell
  `/bin/false` — реальный вход/SSH через неё невозможен, это чисто
  служебная учётная запись для авторизации в Samba), если её ещё нет.
  `ksmbd` этой особенности не имеет — у него собственная база
  пользователей, не связанная с `/etc/passwd`.
- **Права доступа к точке монтирования сделаны полностью открытыми
  (`rwxrwxrwx`) намеренно.** У FAT-семейства (`vfat`/`exfat`/`ntfs3`/
  `ntfs-3g`) unix-права не хранятся на диске — они вычисляются заново при
  каждом монтировании из опций `uid=`/`gid=`/`umask=`. Без явных значений
  итоговые права зависят от того, что записано в ACL/атрибутах на диске —
  на практике встречалась точка монтирования с правами `drwxr--r--` (без
  execute-бита для «прочих») на накопителе, отформатированном сторонним ПО
  (Clonezilla): любой SMB-пользователь, кроме root, получал `Permission
  denied` при заходе в шару, даже с верным логином и паролем (лог `smbd`:
  `vfs_ChDir(...) failed: Permission denied. Current token: uid=N, gid=N`
  — обратите внимание, что это **не** уже описанный выше случай с
  `uid=65535`, а настоящий, но всё равно без прав на сам каталог). Скрипт
  теперь явно монтирует FAT-семейство с `uid=0,gid=0,umask=000`, а для
  ext4/f2fs (настоящие unix-права, опциями монтирования не
  переопределяются) выполняет `chmod 777` на точке монтирования сразу
  после `block mount`. Реальный контроль доступа всё равно выполняет сам
  SMB-сервер (`valid users`/пароль) — на роутере, где кроме `root` никто
  больше локально не заходит, открытые unix-права не ослабляют защиту.
  Если шара была настроена **до** этого исправления — переподключите
  накопитель через `swap-disk`, чтобы права обновились:
  ```sh
  OPENWRT_TOOL_MODE=swap-disk sh /root/openwrt-tool/usb-smb-share.sh
  ```
- **USB 3.0 может создавать помехи Wi-Fi 2.4 ГГц** — общая проблема для
  компактных роутеров. Если просядет скорость на 2.4 ГГц: используйте
  короткий экранированный USB-кабель, разнесите накопитель подальше от
  антенн, либо переключите чувствительных клиентов на 5 ГГц.
- **exFAT**: `OPENWRT_TOOL_FS_TYPE=exfat` монтируется только штатным
  драйвером ядра `kmod-fs-exfat` — в отличие от NTFS, у exFAT в OpenWrt
  нет резервного FUSE-варианта. Если этого модуля нет в индексе пакетов
  прошивки или он не регистрирует файловую систему в `/proc/filesystems`
  (бывает на урезанных сборках), скрипт останавливается с понятным
  сообщением ещё до попытки монтирования — вместо этого переформатируйте
  накопитель в `ext4` или `ntfs3`.
- **FAT32**: `OPENWRT_TOOL_FS_TYPE=vfat` — максимально совместимый формат
  (читается вообще везде), но ограничен файлами до 4 ГБ и разделами до
  ~2 ТБ. Не годится для больших видео/бэкапов.
- **F2FS**: `OPENWRT_TOOL_FS_TYPE=f2fs` — файловая система, оптимизированная
  под флеш-память (флешки, SSD), меньше изнашивает носитель по сравнению с
  ext4. Пакет `kmod-fs-f2fs` есть не на всех прошивках — если недоступен,
  скрипт сразу останавливается с понятным сообщением.
- **NTFS**: `OPENWRT_TOOL_FS_TYPE=ntfs3` работает и на чтение, и на запись.
  Скрипт сначала пробует нативный драйвер ядра `kmod-fs-ntfs3` (быстрее, но
  требует ядро Linux 5.15+, т.е. прошивку не старее OpenWrt 23.05). Если
  такого пакета в прошивке нет — автоматически откатывается на `ntfs-3g`
  (FUSE): тоже полноценное чтение/запись, но медленнее и прожорливее по
  CPU/памяти на файловых операциях. В конце установки скрипт печатает,
  какой драйвер реально используется (`Точка монтирования: ... (драйвер:
  ntfs3|ntfs-3g, ...)`). Отдельно: если диск перед отключением от Windows
  не был штатно извлечён (быстрый запуск/гибернация или разрыв соединения
  без «Безопасного извлечения» оставляют NTFS в «грязном» состоянии),
  монтирование может не пройти вовсе — в `dmesg` будет строка вида
  `ntfs3(sdX): volume is dirty and "force" flag is not set!` (в старых
  версиях драйвера `ntfs3` том в этом случае мог смонтироваться хотя бы
  на чтение, в текущих — просто отказывает, чтобы не писать поверх
  недоигранного журнала). Скрипт эту ситуацию отлавливает сам и пишет
  «Не удалось смонтировать ... Проверьте logread и dmesg». Лечится на
  Windows: `chkdsk X: /f`, затем штатное «Безопасное извлечение
  устройства» перед повторным подключением к роутеру.
- **NTFS и не-латинские имена файлов** (кириллица и т.п.): драйвер `ntfs3`
  конвертирует имена через NLS-таблицу, заданную опцией монтирования
  `iocharset` — без неё использует `CONFIG_NLS_DEFAULT` (латинскую
  кодировку), которая кириллицу не понимает. Симптом в `logread`: поток
  `ntfs3(sdX): failed to convert "0412" to default` (число — код символа
  Unicode, например `0x0412` — кириллическая «В»); в `ls -la` такие файлы
  показывают «мусорное» имя и `No such file or directory`, по SMB не
  видны вовсе. Скрипт сам ставит `kmod-nls-utf8` и добавляет
  `iocharset=utf8` в опции монтирования при выборе `ntfs3` (и в `setup`, и
  в `swap-disk`) — если шара была настроена **до** этого исправления,
  просто переподключите накопитель через `swap-disk` ещё раз, чтобы
  опции монтирования обновились:
  ```sh
  OPENWRT_TOOL_MODE=swap-disk sh /root/openwrt-tool/usb-smb-share.sh
  ```
- Накопителям без внешнего питания (2.5" HDD без USB-хаба с питанием) на
  маломощных роутерах иногда не хватает тока — если диск не определяется,
  проверьте `dmesg` через `OPENWRT_TOOL_MODE=status`.
- Скрипт **не форматирует** диск — если накопитель новый/чужой,
  отформатируйте его заранее на компьютере или через `ssh` вручную.

### Логи

Ход выполнения пишется в `/root/openwrt-tool/usb-smb-share.log`.

### Кнопки на корпусе (опционально, зависит от модели)

Необязательные надстройки над этим скриптом в соседних каталогах — обе
используют режим `swap-disk`, описанный выше, для подключения/безопасного
размонтирования USB-накопителя без захода по SSH:

- **Cudy TR3000** — [`cudy-tr3000`](../cudy-tr3000/README.md):
  короткое нажатие штатной кнопки reset.
- **Cudy WR3000U** — [`cudy-wr3000u`](../cudy-wr3000u/README.md):
  долгое нажатие (5+ сек) кнопки WPS (короткое нажатие там же переключает
  Wi-Fi).

Другим моделям это не подходит — там нет одноимённых кнопок/GPIO с такой
же разводкой.

## Если форкаете этот проект

Этот каталог — часть монорепозитория
[openwrt-tools](https://github.com/imaks79/openwrt-tools), поэтому оба
скрипта ссылаются на себя через `SCRIPT_URL` с префиксом `openwrt-tool/`:

```sh
grep -n '^SCRIPT_URL=' install.sh usb-smb-share.sh
```

Эта константа в каждом скрипте нужна, чтобы он мог скачать сам себя для
повторного запуска (после перезагрузки — у `install.sh`; после первого
запуска — у `usb-smb-share.sh`). Если форкаете или переносите именно этот
каталог в отдельный репозиторий — поменяйте обе константы (или полный
путь, если у нового репозитория нет такого подкаталога). Если также
переносите `cudy-tr3000` или `cudy-wr3000u` —
их `reset-button-usb-toggle.sh` и `wps-button-wifi-toggle.sh`
соответственно жёстко ссылаются на `/root/openwrt-tool/usb-smb-share.sh`,
эту ссылку нужно обновить отдельно (см. README в соответствующем
каталоге).
