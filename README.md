# cudy-tr3000-usb-share

Скрипт `install.sh` превращает USB 3.0 порт роутера Cudy TR3000 (прошивка
на базе OpenWrt/LuCI) в сетевой общий каталог (SMB/CIFS) — доступный с
Windows, macOS, Linux, Android и iOS. Работает через `ksmbd` (лёгкий
SMB-сервер в ядре Linux) с автоматическим откатом на `samba4`, если
`ksmbd-server` недоступен в вашей прошивке. Выбор в пользу `ksmbd` — из-за
малого объёма флеша роутера (256 МБ).

## Быстрый старт

На роутере включён SSH (обычно настраивается один раз в веб-интерфейсе:
**System → Administration** или аналогичный раздел в интерфейсе Cudy), к
USB 3.0 порту подключён накопитель (можно подключить и позже — скрипт
подождёт до 60 секунд), отформатированный **заранее** в `ext4`
(рекомендуется), `exfat` или `ntfs3` — сам скрипт диск не форматирует и не
размечает (осознанное ограничение, чтобы случайно не стереть чужие данные).

Подключитесь к роутеру по SSH и вставьте одну строку:

```sh
wget -O - https://raw.githubusercontent.com/imaks79/cudy-tr3000-usb-share/main/install.sh | sh
```

Роутер сам обновит списки пакетов, поставит нужные модули (USB 3.0,
файловая система, SMB-сервер), найдёт накопитель, настроит автомонтирование
по UUID и сетевую шару. В процессе один раз **дважды попросит ввести пароль**
для нового SMB-пользователя (по умолчанию `cudyuser`) — обычный интерактивный
ввод внутри SSH-сессии, пароль нигде на диске не сохраняется. Перезагрузка
роутеру не требуется.

## Как это работает

Исходно проект состоял из скрипта, который запускался **с вашего
компьютера** и по SSH/SCP копировал на роутер набор отдельных файлов
(установка, статус, cron-алерт, смена диска). Теперь всё объединено в один
`install.sh`, который скачивается и выполняется **прямо на роутере** —
как и `openwrt-tool`.

Особенность в том, что при запуске через `wget -O - ... | sh` стандартный
ввод самого скрипта уже занят телом скрипта, поэтому:

- выбор раздела (если к роутеру подключено сразу несколько
  USB-накопителей) читает ответ явно из `/dev/tty` — реального терминала
  SSH-сессии, а не из перекрытого stdin;
- создание SMB-пользователя (`ksmbd.adduser`/`smbpasswd`) само запрашивает
  пароль напрямую через терминал и пайпа не боится.

Настройка (в отличие от `openwrt-tool`) не требует перезагрузки роутера,
поэтому скрипту не нужно переживать ребут и продолжать себя после него —
вся работа укладывается в один проход. Скрипт всё же сохраняет свою копию в
`/root/cudy-tr3000-usb-share/install.sh`, чтобы дальнейшие команды
(статус, смена диска, cron-алерт) можно было запускать повторно без
повторного скачивания.

## Настройка перед публикацией на GitHub

`SCRIPT_URL` в `install.sh` уже указывает на raw-адрес файла в этом
репозитории:

```sh
SCRIPT_URL="https://raw.githubusercontent.com/imaks79/cudy-tr3000-usb-share/main/install.sh"
```

Если форкаете или переносите проект в другой репозиторий — поменяйте
`<USER>/<REPO>` на свои (в комментарии сверху `install.sh` и в примерах
ниже тоже).

## Переменные окружения

Все опциональны, задаются перед командой:

```
CUDY_MOUNT_POINT      точка монтирования USB (по умолчанию /mnt/usb1)
CUDY_FS_TYPE           ext4 | exfat | ntfs3 (по умолчанию ext4)
CUDY_SHARE_NAME        имя сетевой шары (по умолчанию share)
CUDY_WORKGROUP         рабочая группа SMB (по умолчанию WORKGROUP)
CUDY_SMB_USER          логин для доступа к шаре (по умолчанию cudyuser)
CUDY_GUEST             1 — разрешить анонимный доступ (не рекомендуется)
CUDY_WITH_CRON_ALERT   1 — сразу поставить ежедневную проверку заполнения диска
CUDY_MODE              setup (по умолчанию) | status | swap-disk | cron-alert
```

### Примеры

Накопитель в exFAT и своё имя шары:

```sh
CUDY_FS_TYPE=exfat CUDY_SHARE_NAME=movies \
  wget -O - https://raw.githubusercontent.com/imaks79/cudy-tr3000-usb-share/main/install.sh | sh
```

Настройка сразу с ежедневным алертом о заполнении диска:

```sh
CUDY_WITH_CRON_ALERT=1 \
  wget -O - https://raw.githubusercontent.com/imaks79/cudy-tr3000-usb-share/main/install.sh | sh
```

Гостевой (анонимный) доступ без пароля:

```sh
CUDY_GUEST=1 \
  wget -O - https://raw.githubusercontent.com/imaks79/cudy-tr3000-usb-share/main/install.sh | sh
```

## Режимы после первоначальной настройки

Скрипт сохраняет себя в `/root/cudy-tr3000-usb-share/install.sh` — эти
команды выполняются на роутере и не требуют переустановки пакетов:

**Статус** (место на диске, скорость линка USB, статус SMB-службы, логи):

```sh
CUDY_MODE=status sh /root/cudy-tr3000-usb-share/install.sh
```

**Смена физического накопителя** (другая флешка/диск, другой UUID,
возможно другая файловая система) — отмонтирует старый накопитель,
дождётся (до 60 сек) нового, определит его файловую систему автоматически
(ext4/exfat/vfat/ntfs — доустановит нужный модуль при необходимости,
включая откат ntfs3→ntfs-3g), обновит точку монтирования. Шара, логин и
пароль остаются прежними — клиентам ничего менять не нужно:

```sh
CUDY_MODE=swap-disk sh /root/cudy-tr3000-usb-share/install.sh
```

Если это **та же самая флешка** (просто вынули/вставили обратно, или после
перезагрузки роутера) — запускать ничего не нужно. Монтирование привязано
к UUID конкретного накопителя (`/etc/config/fstab`), и роутер сам
примонтирует его и поднимет шару по прежнему пути.

**Ежедневный алерт о заполнении диска** отдельно от первоначальной
настройки (пишет в syslog предупреждение, если диск заполнен на 90% и
более, тег лога `usb-storage-alert`):

```sh
CUDY_MODE=cron-alert sh /root/cudy-tr3000-usb-share/install.sh
```

Посмотреть сработавшие алерты:

```sh
logread | grep usb-storage-alert
```

Скрипт идемпотентен: `CUDY_MODE=setup` можно запускать повторно (например,
чтобы поменять параметры) — старые UCI-секции с тем же именем удаляются
перед созданием новых.

## Что скрипт делает на роутере (режим setup)

1. `opkg update` и установка пакетов: `kmod-usb3`, `kmod-usb-storage`,
   `kmod-usb-storage-uas`, `block-mount`, `e2fsprogs`, `fdisk`, модуль
   нужной файловой системы, и `ksmbd-server` + `luci-app-ksmbd` (либо
   `samba4-server` + `luci-app-samba4`, если `ksmbd` недоступен).
2. Ищет подключённый USB-накопитель **строго среди `/dev/sdX`** (так в
   OpenWrt всегда называются диски, подключённые через USB-storage) —
   внутренние разделы прошивки роутера никогда не трогаются. Если
   накопитель ещё не подключён, скрипт **ждёт до 60 секунд**, опрашивая
   каждые 3 секунды. Если найдено несколько разделов — спросит, какой
   использовать (ответ читается из `/dev/tty`).
3. Настраивает автомонтирование по UUID через UCI (`/etc/config/fstab`) —
   монтирование переживёт перезагрузку и не зависит от того, в каком
   порядке система пронумеровала диски.
4. Создаёт SMB-шару, ограниченную только что созданным пользователем
   (`CUDY_GUEST=1` снимает это ограничение).
5. Создаёт SMB-пользователя и запрашивает пароль интерактивно.
6. Включает и перезапускает SMB-службу.
7. (опционально, `CUDY_WITH_CRON_ALERT=1`) Ставит cron-задачу, которая раз
   в день в 08:00 пишет в syslog предупреждение, если диск заполнен на 90%
   и более.
8. Печатает текущий статус (как в режиме `status`).

## Как пользоваться готовой шарой

- **Windows**: в проводнике `\\<ip роутера>\share`, ввести логин/пароль.
- **macOS**: Finder → `Cmd+K` → `smb://<ip роутера>/share`.
- **Linux**: `smb://<ip роутера>/share` в файловом менеджере, либо
  `sudo mount -t cifs //<ip роутера>/share /mnt/point -o username=cudyuser`.
- **Android/iOS**: любое приложение с поддержкой SMB (Solid Explorer,
  FE File Explorer и т.п.), сервер `<ip роутера>`, шара `share`.

Перед физическим отключением накопителя — размонтировать на роутере:

```sh
umount /mnt/usb1
```

## Мониторинг

В любой момент, прямо на роутере:

```sh
CUDY_MODE=status sh /root/cudy-tr3000-usb-share/install.sh
```

Покажет: место на диске, скорость линка USB (`5000` = USB 3.0,
`480` = USB 2.0 — если видите 480, проверьте кабель/порт), статус
SMB-службы, последние сообщения ядра про USB и последние записи журнала по
SMB.

Через LuCI (веб-интерфейс роутера): **System → Mount Points** — список
смонтированных дисков; **Services → Network Shares** (после установки
`luci-app-ksmbd`/`luci-app-samba4`) — активные шары.

## Известные особенности

- **USB 3.0 может создавать помехи Wi-Fi 2.4 ГГц** — общая проблема для
  компактных роутеров. Если просядет скорость на 2.4 ГГц: используйте
  короткий экранированный USB-кабель, разнесите накопитель подальше от
  антенн, либо переключите чувствительных клиентов на 5 ГГц.
- **NTFS**: `CUDY_FS_TYPE=ntfs3` работает и на чтение, и на запись. Скрипт
  сначала пробует нативный драйвер ядра `kmod-fs-ntfs3` (быстрее, но
  требует ядро Linux 5.15+, т.е. прошивку не старее OpenWrt 23.05). Если
  такого пакета в прошивке нет — автоматически откатывается на `ntfs-3g`
  (FUSE): тоже полноценное чтение/запись, но медленнее и прожорливее по
  CPU/памяти на файловых операциях. В конце установки скрипт печатает,
  какой драйвер реально используется (`Точка монтирования: ... (драйвер:
  ntfs3|ntfs-3g, ...)`). Отдельно: если диск перед отключением от Windows
  не был штатно извлечён (быстрый запуск/гибернация оставляют NTFS в
  «грязном» состоянии), Linux может смонтировать его только на чтение —
  тогда перед подключением к роутеру нужно один раз безопасно извлечь диск
  на Windows или прогнать `chkdsk`.
- Накопителям без внешнего питания (2.5" HDD без USB-хаба с питанием) на
  маломощных роутерах иногда не хватает тока — если диск не определяется,
  проверьте `dmesg` через `CUDY_MODE=status`.
- Скрипт **не форматирует** диск — если накопитель новый/чужой,
  отформатируйте его заранее на компьютере или через `ssh` вручную.

## Логи

Ход выполнения пишется в `/root/cudy-tr3000-usb-share/install.log`.

## Дополнительно: Wi-Fi по переключателю "mode" + красный LED

Отдельная, не связанная с USB-шарой утилита для этого же роутера:
физический флажок "mode" на Cudy TR3000 включает/выключает Wi-Fi, а пока
Wi-Fi выключен — вместо белого статусного светодиода горит красный.

Установка одной строкой (лучше по кабелю/LAN — см. предупреждение ниже):

```sh
wget -O - https://raw.githubusercontent.com/imaks79/cudy-tr3000-usb-share/main/install-mode-button.sh | sh
```

Скрипт `install-mode-button.sh` скачивает `mode-button-wifi-toggle.sh` и
кладёт его в `/etc/rc.button/BTN_0` — так называется хук, который procd
вызывает на каждое физическое переключение флажка (переменная `BUTTON`
для этого GPIO равна `BTN_0`, хотя в device tree он подписан как "mode").
Также добавляет путь в `/etc/sysupgrade.conf`, чтобы файл пережил
обновление прошивки (`sysupgrade` без `-n` сохраняет только файлы из
этого списка).

Логика:

- Положение переключателя однозначно определяет желаемое состояние сети
  (`pressed` → Wi-Fi включён, `released` → выключен) — команда не
  повторяется, если сеть уже в нужном состоянии (защита от лишних
  перезапусков при повторных/дребезжащих событиях).
- Пока Wi-Fi выключен, гаснет штатный белый светодиод (`white:status`,
  на этой прошивке горит статически, без автотриггера) и загорается
  красный (`red:power`).

Имена LED (`red:power` / `white:status`) проверены на Cudy TR3000 256MB
v1 (OpenWrt 25.12.5, mediatek/filogic). На другой модели/прошивке сначала
проверьте `ls /sys/class/leds/` на роутере и при необходимости
переопределите перед установкой:

```sh
LED_RED_DIR=/sys/class/leds/<имя> LED_WHITE_DIR=/sys/class/leds/<имя> \
  wget -O - https://raw.githubusercontent.com/imaks79/cudy-tr3000-usb-share/main/install-mode-button.sh | sh
```

**Важно:** если вы зашли по SSH через сам Wi-Fi (а не по кабелю), то
переключение флажка в положение "выключено" оборвёт и вашу же SSH-сессию
вместе с сетью. Устанавливайте и тестируйте по LAN-кабелю. Проверить
логику без физической кнопки:

```sh
ACTION=released BUTTON=BTN_0 /etc/rc.button/BTN_0
ACTION=pressed  BUTTON=BTN_0 /etc/rc.button/BTN_0
```
